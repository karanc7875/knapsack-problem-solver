04 / UNDERSTAND THE METHODS

Algorithm guide

01

Dynamic Programming

Builds solutions for every prefix of the items and every capacity. Each cell asks whether the current item improves the best value so far.

dp[0][c] = 0
for i = 1..n:
  for c = 0..W:
    dp[i][c] = dp[i-1][c]
    if weight[i] ≤ c:
      dp[i][c] = max(dp[i][c],
                     value[i] + dp[i-1][c-weight[i]])

Time: O(nW) · Space: O(nW)

Pros: Always optimal; reconstructs the selected items.
Cons: Capacity-dependent memory and runtime.

02

Greedy by ratio

Sorts by value per unit of weight, then takes each item that fits. This is optimal for fractional knapsack, but not in general for 0/1 knapsack.

sort items by value / weight
for item in sorted items:
  if item.weight fits:
    take item

Time: O(n log n) · Space: O(n)

Pros: Very fast and easy to understand.
Cons: Can miss the optimal 0/1 solution.

03

Backtracking + pruning

Explores include/exclude choices. It prunes overweight branches and branches whose fractional-knapsack upper bound cannot beat the best solution already found.

search(i, weight, value):
  update best with current choice
  if overweight or bound ≤ best: return
  search(i+1, include item i)
  search(i+1, exclude item i)

Time: O(2n) worst case · Space: O(n)

Pros: Exact; bounds can skip large parts of the tree.
Cons: Still exponential in the worst case.

04

Plain recursion

Evaluates both include and exclude choices for every item without pruning. This provides a baseline for measuring the impact of branch-and-bound.

search(i, weight, value):
  if i == n: update best; return
  search(i+1, include item i)
  search(i+1, exclude item i)

Time: O(2n) · Space: O(n)

Pros: Simple exact reference implementation.
Cons: Explores every subset; skipped above 25 items.
